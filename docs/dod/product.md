# Commit Replay Bench

**Purpose.** Commit Replay Bench replays an organisation's own commits to find the least
context each kind of change needs — its tests, and the signed project knowledge around them —
for an AI builder to pass the repository's own held-out tests at a proven rate, and lets a
ticket into manufacturing only when it carries that context.

"Proven" means the look rule of `product.truth.202`, a pre-registered bound on the
first-attempt clean rate against the repository's own tests; it means neither correct nor
working, which stays `product.value.102`'s reviewed reading (ADR-0026, DL-098). README's first
sentence changes to the purpose sentence above when G-600 is closed.

**Entry → exit.** A regulated organisation installs the signed image on its own infrastructure
with its own model keys, signs in, connects one repository, proves the instrument on it for
£0, and measures. It leaves with a capability map whose every cell names the context its
changes need — its proven standard, or "no proven standard" and the next measurement — with
`n`, a Wilson 95% interval and the apparatus version, a route per class of change (`deliver` /
`calibrate` / `granularize` / `human`), a second person's signature on the cells that clear
the bar, and a pull request on its own repository that a human merges.

**Non-goals.** Not a leaderboard, not an AI's opinion of an AI's work, not a proof of semantic
correctness, not a licence to deploy. It does not merge anything itself, keeps the redacted
patch it graded (ADR-0006) but no transcript or worktree by default, does not reach the public
internet from a worker, and never moves code or identifiers between tenants — only abstract
cells. It does not decide an organisation's standards — it proposes, measures and records the
ones that organisation's people sign — and it never certifies that code conforms to ISO/IEC
25010, ISO/IEC 5055 or any other standard.
