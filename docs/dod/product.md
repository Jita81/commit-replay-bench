# Commit Replay Bench

**Purpose.** Commit Replay Bench grades an AI builder against a repository's own held-out
tests, and delivers new change as branches and pull requests only in the cells that evidence
licenses (README; DL-044).

**Entry → exit.** A regulated organisation installs the signed image on its own
infrastructure with its own model keys, signs in, connects one repository, proves the
instrument on it for £0, and measures. It leaves with a capability map whose every cell
carries `n`, a Wilson 95% interval and the apparatus version, a route per class of change
(`deliver` / `calibrate` / `granularize` / `human`), a second person's signature on the cells
that clear the bar, and a pull request on its own repository that a human merges.

**Non-goals.** Not a leaderboard, not an AI's opinion of an AI's work, not a proof of
semantic correctness, not a licence to deploy. It does not merge anything itself, does not
keep raw diffs or transcripts by default, does not reach the public internet from a worker,
and never moves code or identifiers between tenants — only abstract cells.

## Gaps
- **G-605** — the definition-of-done artefacts make quantitative claims of their own (a journey's minutes and £, a page's counts, a stream's current state) and carry no tags, so the rule the product applies to its own guides does not yet apply to the record of what done means (CodeRabbit on PR #47) · decide the rule in `scripts/claims_check.py` (criterion text is a specification, not a claim; prose and quantitative statements are claims; never a tag in a gap id or an evidence reference) and apply it to `docs/dod/**` · docs
- **G-600** — the identity sentence lives in the README only: no screen states what the product is (Home's About block describes the task list, not the product), and the long-form account of the product is not in this repository, so three readers get three different first sentences · put the README's first sentence verbatim in the `/home` About block and in `/help`'s index, and add a test that the three strings are one string · ui
- **G-601** — nothing in the product records the last `row_hash` anywhere but the database it protects, so an operator who replaces the whole store cannot be caught by the product's own verification; the go-live line is a manual `SELECT` whose result lives in a wiki · serve the current head `row_hash` on `/ledger/verify` as a value meant to be copied out, and write it to the run log at every worker start so it lands in the log store · server
- **G-602** — the four alert rules exist as expressions in DEPLOYMENT §9.2 but no alert manifest ships, so each deployment retypes them and a typo is silent · ship a `PrometheusRule` template in the chart, off by default, with the four rules and a Helm template test · deploy
- **G-605** — the claims gate covers two pages: the README and RELEASING are read by CI's `claims` job, so a wrong number in SECURITY, DEPLOYMENT, OPERATOR, ARCHITECTURE, the reviews or the book still waits for a reader to find it · add each page to `scripts/claims_check.py`'s ALLOWLIST and tag or correct what the gate then finds, one page per change · docs
- **G-604** — no signed release contains the shippable wave: the four version numbers still read `2.0.0a1`, the CHANGELOG's `Unreleased` section is uncut, the `release.yml` dry run after the action bumps is not evidenced, the Helm chart is not published as an OCI artifact, and no tag-protection ruleset exists for `v*` · cut `2.0.0b1` per RELEASING §2 steps 1–8 once `feat/shippable` is on `main` · deploy
