# Recover an account

**Purpose.** A person who cannot sign in gets back in — and a leaver stops being able to — without emptying the `users` table: an admin sets a new password or clears the active flag, or, when no admin can sign in at all, the host operator does it with `crb users` on the API host, and every change is one `user.*` event with an actor and a target, which the account's own History on `/settings` renders (OPERATOR §9).

**Entry → exit.** Entry is a failed sign-in on `/login` (the 401 envelope), or an admin who has to disable a leaver. Exit is a person who signs in again, or an account that is refused on its next request, with one `user.*` event recorded and the account's other sessions ended. Nothing on this journey spends money. The acts are on `/settings` — the Users card sets a password, turns an account off and on, changes a role, creates a local account and shows that account's history, and the "Change my password" card is the self-service door — and the same acts are at the API (`PUT /users/{id}/password`, `PUT /users/me/password`, `PUT /users/{id}/active`) and on the host (`crb users set-password | activate | deactivate | create`). The other screen on the path is `/login`, which shows the envelope and does not yet name who can set a new password.

**Non-goals.** No email or self-service reset link, no unlock code and no security questions: the second door is the host, not the person's inbox. An account that signs in through the organisation's identity provider has no local password — its recovery and its disabling are the provider's, and the API refuses both with 409 `not_local`. Rotating the bootstrap admin at go-live is dod.journey.deploy-and-go-live; the pages on this path (`/login`, `/settings`) are owned by dod.journey.orient and dod.journey.deploy-and-go-live, so this artefact carries no page children.
