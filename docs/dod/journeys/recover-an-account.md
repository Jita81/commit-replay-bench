# Recover an account

**Purpose.** A person who cannot sign in gets back in — and a leaver stops being able to — without emptying the `users` table: an admin sets a new password or clears the active flag, or, when no admin can sign in at all, the host operator does it with `crb users` on the API host, and every change is one `user.*` event with an actor and a target (OPERATOR §9; no screen states this today).

**Entry → exit.** Entry is a failed sign-in on `/login` (the 401 envelope), or an admin who has to disable a leaver. Exit is a person who signs in again, or an account that is refused on its next request, with one `user.*` event recorded and the account's other sessions ended. Nothing on this journey spends money. The acts exist at the API (`PUT /users/{id}/password`, `PUT /users/me/password`, `PUT /users/{id}/active`) and on the host (`crb users set-password | activate | deactivate | create`); the only in-product screen on the path is `/settings`, whose Users card lists accounts, changes a role and creates a local account, and `/login`, which offers nothing.

**Non-goals.** No email or self-service reset link, no unlock code and no security questions: the second door is the host, not the person's inbox. An account that signs in through the organisation's identity provider has no local password — its recovery and its disabling are the provider's, and the API refuses both with 409 `not_local`. Rotating the bootstrap admin at go-live is dod.journey.deploy-and-go-live; the pages on this path (`/login`, `/settings`) are owned by dod.journey.orient and dod.journey.deploy-and-go-live, so this artefact carries no page children.
