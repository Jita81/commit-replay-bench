# Manufacture (freeze → run → PR → outcome)

**Purpose.** New work is delivered under the same rules as replay: a frozen, hashed backlog, a failing test proved RED before any build, a build under the same belts inside the sandbox, an independent review, and a branch and pull request on the customer's repository only where the measured map routes `deliver` — never on their default branch. The operator freezes and runs; an approver signs structural gaps and owns any override; a viewer reads the chain (ONBOARDING step 8; DL-044).

**Entry → exit.** Arrives from Home task 8 ("Deliver your first change"), which cannot start until the repository is measured and a cell routes `deliver`, or straight from the Factory nav item. The person leaves with a pull request on the customer's repository — its link on the item row — or the sentence that says why delivery was withheld, and with every step of each item (readiness, RED proof, build, delivery, review, outcome) on the hash-verified factory evidence chain. The pull request's fate (merged or closed) comes back once per pull request as `delivery.merged` / `delivery.closed`, which is what completes Home task 8.

**Non-goals.** It does not take work from a ticket system: a backlog is typed or pasted here (that journey is `dod.journey.intake-from-a-ticket`). It does not measure a cell or sign one off — it consumes the signed map's route. It does not merge the pull request: the merge is the customer's decision, recorded as evidence afterwards. It never writes to the customer's default branch, and it does not review the diff it produced (that verdict is recorded on `/runs/:id`).
