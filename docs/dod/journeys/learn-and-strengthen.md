# Learn and strengthen an oracle

**Purpose.** Turn what the ledger recorded into work a person decides on: refusals become
candidate guard-corpus lines, weak oracles become test work, and evidence that predates the
current apparatus becomes a priced re-measurement plan. In the product's own words: "What the
ledger teaches, as three reports … Nothing here acts; a person does" (`help.ts` About copy for
`/learn`). The operator triages and queues, the repository's test owner writes the tests, and a
named person writes each refusal verdict.

**Entry → exit.** Arrive at `/learn?repo=` from the Instrument nav entry `Learn`
(`Layout.tsx:121`) — the loop has no entry on Home and no journey position, so a person finds
it only by knowing it is there. Ordered path: read the three reports → open `/oracle?repo=` for
the weak cells and a task's escaped mutants → strengthen the target tests in the repository
(outside the product, by design) → re-score the oracle and re-run the negative controls →
freeze the strengthening item on `/factory` and queue the re-measurement runs from `/runs` →
write the refusal verdicts with `crb learn refusals --apply`. Leave with a strengthened cell
re-measured on the current apparatus, deliver no longer withheld for `oracle_weak` or
`controls_escapes`, and a guard-corpus line that carries its decider and provenance.

**Non-goals.** The loop never decides for the person: the product appends no corpus line,
freezes no item, queues no spend and writes no verdict. It does not write the repository's
tests (a person does, in the repository), does not re-mine a repository's history to re-qualify
a task, and never blends a rate across apparatus versions to make a cell look measured.
