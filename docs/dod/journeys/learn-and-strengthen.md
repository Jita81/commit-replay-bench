# Learn and strengthen an oracle

**Purpose.** Turn what the ledger recorded into work a person decides on: refusals become
candidate guard-corpus lines, weak oracles become test work, and evidence that predates the
current apparatus becomes a priced re-measurement plan. In the product's own words: "What the
ledger teaches, and what the loop does about it … The product decides nothing on its own: the
register acts only under an operator's switch, and each report's decision is made here by an
operator and recorded with their name" (`help.ts` About copy for `/learn`). The operator
triages and queues, the repository's test owner writes the tests, and a named person writes
each refusal verdict — since 2026-09-23 from the page that showed them the reason, rather than
as a command on the host.

**Entry → exit.** Arrive at `/learn?repo=` from the Instrument nav entry `Learn`
(the `INSTRUMENT` list in `Layout.tsx`) — the loop has no entry on Home and no journey position, so a person finds
(`Layout.tsx:121`), or at `/learn?repo=#strengthen` from the screen that revealed the need: a
cell withheld for its oracle on the Baseline map, the controls gate on Oracle, an amber controls
stage on the Connection walk, or an item the Factory stopped for a weak test. The loop has no
entry on Home and no position in the journey bar; the Learn page, the Oracle gate's link and a
Runs dialog opened from Learn each say which of the loop's six steps the reader is on. Ordered path: read the three reports → open `/oracle?repo=` for
(every role: `INSTRUMENT` in `Layout.tsx`) — the loop has no entry on Home and no journey position, so a person finds
the weak cells and a task's escaped mutants → strengthen the target tests in the repository
(outside the product, by design) → re-score the oracle and re-run the negative controls →
re-qualify, re-score and re-run the controls from the item's row (the Runs dialog opens with the
kind and the task filled in) → register the strengthening item and queue the re-measurement runs
from the reports themselves →
record the refusal verdicts on the same page (or with `crb learn refusals --apply`). Leave with a strengthened cell
re-measured on the current apparatus, deliver no longer withheld for `oracle_weak` or
`controls_escapes`, and a guard-corpus line that carries its decider and provenance.

**Non-goals.** The loop never decides for the person: nothing is appended, registered, spent or
judged except as a named operator's own act, recorded with their identity, and no derivation
carries a verdict. It does not write the repository's tests (a person does, in the repository),
does not re-mine a repository's history to re-qualify a task, and never blends a rate across
apparatus versions to make a cell look measured.
