# The definition of done — one standard, four levels

**Why.** "Done" in this product has been a feeling backed by a growing feature list. That is
how a product accretes screens nobody finishes. From here, done is a *record*: for every page,
every journey, every value stream and the product as a whole there is one artefact of the
same shape that says what done means, what proves it, and how far it is from met. The gap
analysis is not a document someone writes — it is the roll-up of those artefacts
(`docs/dod/GAP-ANALYSIS.md`, generated by `scripts/dod_check.py`, drift-checked in CI like
`CODE-MAP.md`). Nothing gets built because it is a good idea; it gets built because an
artefact names it as a gap.

This is the same discipline the product applies to a customer's repository: a claim carries
its evidence or it is not a claim (`docs/EVIDENCE-AND-CLAIMS.md`). We apply it to ourselves.

## 1. The four levels and how they nest

| level | one per | id | parent |
|---|---|---|---|
| **page** | route in `ui/src/App.tsx` | `dod.page.<route-slug>` (`/repos/:name` → `repos-name`) | the journey step it serves (or `shell`) |
| **journey** | one person's goal, walked as ordered pages | `dod.journey.<slug>` | the value stream it belongs to |
| **value stream** | one flow of value through the product | `dod.stream.<slug>` | `dod.product` |
| **product** | the whole | `dod.product` | — |

A level is done only when its children are done **and** its own criteria are met. A page
cannot be done while its journey has no walkthrough; a journey cannot be done while a page in
it is partial. The roll-up is mechanical (§5).

## 2. The artefact shape

Every artefact is one Markdown file with YAML front matter and one criteria table. The shape
is identical at every level so the checker and a reader treat them alike.

```markdown
---
id: dod.page.results
level: page                # page | journey | stream | product
name: Baseline (the capability map)
scope: /results            # route · journey slug · stream slug · "product"
parent: dod.journey.read-the-map
children: []               # ids, for journey/stream/product
persons: [viewer, operator, approver]   # who it is for, by product role
owner: ui                  # the layer that owns it (ui | server | factory | docs | deploy)
status: partial            # WRITTEN BY THE CHECKER — never by hand
updated: 2026-09-22
---

# <name>

**Purpose.** One sentence, in the product's own words, of the job this does for the person.
(For a page this is the About block's first sentence; for a journey the persona's goal; for
a stream the artefact of value it produces; for the product its identity.)

**Entry → exit.** How the person arrives and what they leave with (page/journey); the trigger
and the outcome artefact (stream); install → first value (product).

**Non-goals.** What this deliberately does not do, so the gap analysis never asks for it.

## Definition of done

| id | category | criterion | evidence | state | gap |
|---|---|---|---|---|---|
| results.purpose.1 | PURPOSE | The About block states the page's job in one sentence and names the journey step | `hint:about:/results` | met | |
| results.truth.2 | TRUTH | Every rendered rate carries n, the interval and the apparatus | `vitest:ui/src/screens/Results/MapTable.test.tsx::"every cell carries n, the interval and the apparatus"` | met | |
| results.evidence.3 | EVIDENCE | The route is walked by a tier-1 spec at 375 and 1280 with axe clean | `spec:ui/e2e/walkthrough/11-screens.spec.ts::"viewer @ 375: every route renders…"` | met | |
| results.actions.4 | ACTIONS | Opening a cell shows its rows and the route reason | `absent` | unmet | G-012 |

## Gaps
- **G-012** — one line: what is missing, the smallest change that closes it, the owner layer.
```

Rules for the table:

- `id` is `<scope-slug>.<category-lower>.<n>`, unique across the tree.
- `criterion` is **observable**: a sentence a tester could mark true or false on the running
  product without asking the author. "Works well" is not a criterion; "the toggle is disabled
  for the last active admin and its hint says why" is.
- `evidence` is one or more typed references (§3), or the literal `absent`.
- `state` ∈ `met | partial | unmet | n/a`. `met` requires at least one evidence reference
  that **resolves** (the checker looks it up). `partial` and `unmet` require a `gap` id.
  `n/a` requires a one-line reason in the gap column (why the category does not apply here).
- `gap` is a `G-nnn` id defined under `## Gaps` in the same file, or an existing `F-`/`B-`
  backlog id from `docs/reviews/2026-09-17-enterprise-front-end.md` §9. The checker looks the
  backlog id up: an id that no §9 row carries is a defect, not a link.
- A gap line reads `- **G-nnn** — what is missing · the smallest change that closes it · owner`,
  and `owner` is one of `ui`, `server`, `factory`, `docs`, `deploy`. (A ` · ` inside quoted
  product copy is allowed; the rule is that the line ends with its owner and carries at least
  the two separators.)
- **A gap id names one piece of work.** Two files may share an id — and must, when the same
  change closes criteria in both — but then the line is identical in both, word for word. The
  checker fails when one id carries two different lines. Ids are allocated from one register
  per band: pages `G-100`–`G-299`, journeys `G-300`–`G-499`, streams `G-500`–`G-599`, the
  product `G-600`–`G-699`, and gaps shared across files `G-900`–`G-999`.

## 3. Evidence references (typed, resolvable)

| prefix | form | resolves when |
|---|---|---|
| `test:` | `test:tests/test_x.py::test_name` | the file exists and defines that test |
| `vitest:` | `vitest:ui/src/…/X.test.tsx::"test title"` | the file exists and contains that title |
| `spec:` | `spec:ui/e2e/walkthrough/NN-x.spec.ts::"test title"` | the file exists and contains that title |
| `hint:` | `hint:ratchet:/route` · `hint:about:/route` · `hint:id:<HintId>` | the route is a `SCREENS` key in `hints-ratchet.*.tsx` · `help.ts` has a `HELP[]` entry for it · the id is in `hints.ts` |
| `route:` | `route:GET /health` (the path as `docs/API.md` lists it, no `/api/v1`) | `docs/API.md` lists it |
| `code:` | `code:src/crb/core/signoff.py::same_actor_refusal` | the file defines that symbol |
| `doc:` | `doc:docs/OPERATOR.md#9-users` | the file exists and the heading anchor resolves |
| `ci:` | `ci:sandbox-images` | `.github/workflows/ci.yml` has that job |
| `adr:` / `dl:` | `adr:0016` · `dl:DL-047` | the ADR file exists · the row is in `DECISION-LOG.md` |
| `measured:` | `measured:<free text with n, method, apparatus>` | never resolved by the checker; allowed only alongside another reference |

References in one cell are separated by ` · ` or `; `, and the checker cuts only where the
next typed prefix begins — so a quoted `vitest:` or `spec:` title may itself contain ` · `
(Layout's `Journey · n of 4 · Step`) without being torn into unresolvable pieces.

`absent` is honest and expected; a criterion whose only evidence is prose is `unmet`.

## 4. The categories — the same questions at every level

Every artefact answers every category (or marks it `n/a` with a reason). They are the
questions an NHS platform team, a tech lead and a governance reviewer ask, in the order they
ask them.

| code | the question | what met looks like |
|---|---|---|
| **PURPOSE** | Can the person say what this is for? | one-sentence purpose in the product itself (About block / eyebrow / guide), not only in docs |
| **ENTRY-EXIT** | Do they know how they got here and what to do next? | arrived by a named path; the next step is one click; no dead end; the 404 and the empty state say what to do |
| **TRUTH** | Is every number and state honest? | n, interval, apparatus and method on every figure; no fabricated default (audit the *served* default); false-Q1 = 0 stated where it applies; claims tagged |
| **ACTIONS** | Does every action say what it did? | every button/form has a success state that names the outcome and an error that says what to do; destructive actions confirm; long actions show progress and can be cancelled |
| **EXPLANATION** | Is every element explained where it stands? | ratchet-enforced hints on every element; About block; a guide anchor; GOV.UK plain English |
| **EVIDENCE** | Is done proven, not asserted? | unit + route tests; the journey walked by a tier-1 spec at 375 and 1280; axe WCAG 2.1 AA; the criterion's evidence resolves |
| **ROLES** | Is the right person the only person who can? | role gate at the API *and* the UI; an audit event with actor and target; separation of duties where it applies |
| **OPERATIONS** | Can the platform team run and support it? | `/health` and `doctor` know about it; telemetry names it; OPERATOR/API/DEPLOYMENT rows; a stop condition has a way forward |
| **ACCESSIBILITY** | Can everyone use it? | keyboard-only pass; focus management; live regions for toasts; 375 px without horizontal scroll; reduced motion |
| **NON-GOALS** | Is what it does *not* do written down? | a stated non-goal list, so the gap analysis stops asking |

Journeys add: **STEPS** (each step leaves the person with the thing the next step needs; none
requires retyping what the product knows), **PROOF** (one spec walks it end to end, as the
persona), **TIME-COST** (the guide says how long and how much, measured), **RECOVERY** (every
stop condition on the path has a named way forward).

Value streams add: **TRIGGER** (what starts it — a person, an event, a ticket), **OUTCOME**
(the artefact of value and where it lands — a signed cell, a PR on the customer's repository,
a ticket comment), **HANDOFF** (the next stream starts from this one's output without a
person carrying data by hand), **MEASURE** (the product measures the stream's own lead time,
cost and counts and shows them), **AUTOMATION** (no step needs a person to type what the
product already knows).

The product adds: **IDENTITY** (one sentence, the same in README, Home and the book),
**GO-LIVE** (every checklist line is proven by the product, not ticked by belief), **CLAIMS**
(every public claim tagged with its evidence), **RELEASE** (a tagged, signed release exists
per RELEASING.md), **POSTURE** (SECURITY §5 has no untagged gap), **SUPPORT** (the guides are
bundled and current), **EXTENSIBILITY** (DL-044: the extension points a using team improves
are named and exercised).

## 5. The roll-up (what the checker computes)

- criterion state as written; `met` demoted to `partial` if no evidence reference resolves.
- **page** status: `done` when every criterion is `met`/`n/a`; `partial` when any is
  `partial`/`unmet`; `missing` when the route has no artefact.
- **journey** status: `done` when every child page is `done` and its own criteria are met.
- **stream** status: `done` when every child journey is `done` and its own criteria are met.
- **product** status: `done` when every stream is `done` and its own criteria are met.
- Every route in `App.tsx` must have a page artefact; every `JOURNEY_STEPS` entry a journey;
  every stream a parent chain to `dod.product`. A missing artefact fails the check.
- `GAP-ANALYSIS.md` lists, per level, the status, then the open criteria ranked by
  (level weight × count of criteria the gap blocks, capped at 3 × severity of the category ×
  the state factor), so the first line is the one that unblocks the most "done". The state
  factor doubles `unmet` everywhere, and doubles `partial` too in TRUTH, CLAIMS, ROLES and
  POSTURE: where the criterion is about telling the truth, built-wrong is not a lesser defect
  than not-built. The first 25 rows are *the order of work*; *Open gaps by fan-out* repeats
  them as one row per gap, with how many criteria and which levels that one change closes.

## 6. What this is for

The next feature is the top of `GAP-ANALYSIS.md`, or it is not the next feature. A pull
request that adds a screen without a page artefact, or a stream step without its criterion,
fails the `dod` CI job. When a gap closes, the author changes the criterion's `state` and
evidence in the artefact in the same PR; the checker verifies the evidence resolves.
