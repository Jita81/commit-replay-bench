# Classes of work

**Purpose.** An organisation's own classes of work, each a child of one global class, with one
rule that reads only what a ticket carries; a version routes nothing until people have labelled
a sample, its validity report passes and an approver other than its sponsor has signed it
(`help.ts` About copy; ADR-0026 item 9, DL-330).

**Entry → exit.** Arrives from a repository's context library (*Your organisation's classes of
work*) and goes back to it. The person leaves having read a version — its classes, its validity
report with every measure's result, n and state, and how its commits were held out — and one
class's page: what the work is and what its global parent means, the rule in words, example
derivation commits, what a ticket in it must carry (or that its parent sets no question yet), the
signed context its builder would get (with a link to each repository's library page for it) and
what is proven per size; or having proposed a version (and so sponsored it), labelled derivation
commits of a version someone else proposed, signed a version someone else proposed, or revoked
one with a reason.

**Non-goals.** It does not let one person both propose and sign a version (`same_person`, never
relaxed), nor let the sponsor label its sample (`sponsor_label`). It does not show a labeller the
class the rule gives the commit they are labelling, another person's label or any outcome, nor
offer a commit shown as a class's example, and it withholds the agreement from a labeller until
their sample is done; it does not hide the rules in words, which each class's page shows. It
does not license a class on a commit that derived it, measure a class (only a registered reading
does, Wave 5), or change the global classes.

## Gaps
- **G-764** — there is no merge, split or separation-test tool: a sponsor changes a class set only by proposing the next version by hand, and nothing tests whether a child class's first-attempt rate differs from its parent's on derivation outcomes before it is proposed (ADR-0026 item 9 names all three) · add `POST /classes/{org}/v/{n}/separation` (derivation commits only, refusing a confirmation commit as `refuse_reading_pool` does) and merge and split acts that propose version N+1, each shown on the version, and flip `classes.actions.16` · server
- **G-762** — a class-set version waiting for its second person is not a Decisions row, so an approver learns of it only by opening Classes of work · add a `class_set_unsigned` decision kind that the Decisions inbox reads from `DbClassSets`, with a Sign link to `/classes?org=&v=`, and flip `classes.operations.11` · ui
- **G-763** — the capability map and `/routes` select a class-set version (`?taxonomy=`) but group its rows by the global parent, so two classes of one parent show as one cell there; only the class's page and the entry gate read the organisation class's own cell, so the Decisions inbox, which reads the map's cells, never asks for that cell's sign-off and the map serves no `signed` on an organisation's view · project the map by the label table's organisation class when an organisation's version is selected, and flip `classes.truth.14` · server
