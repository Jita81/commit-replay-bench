# Measure — this step spends money

**Purpose.** "Choose how many attempts to buy and what to keep, then start the first sighted measurement. This is the step that spends money, and it says how much before you confirm." (`help.ts`, About block; the kicker reads `Journey · 1 of 4 · Connection · task 5 of 8 · this step spends money`.)

**Entry → exit.** Arrive from Home task 5 "Measure — spends money" (`HomePage.tsx:176`, the only inbound link). Pick 10, 30 or 60 attempts, the two retention switches, read "Before you start" (estimated cost, builder, budget cap, retention, posture), press the red button that names the estimate. On success the page posts `POST /runs {kind: replay, mode: sighted, builder, model, limit, retain}` and returns to `/connect/:name` with the run watched (`MeasurePage.tsx:151-166`). While a replay is already queued or running, a banner names it with "Open the run" (`/runs/:id`) and "Back to the walk"; the button and the estimate are withheld. "Every knob" opens `/runs`; a repository with no gold-clean task is sent to `/repos/:name`.

**Non-goals.** No spend cap: the request carries none and the Budget cap row says so (F5b). No blind mode, budget ladder, `preflight`, `outage_stop`, builder or model choice — the full run form at `/runs` has them. Does not show the run's rows or log (the run page does). Does not decide the posture — it reads the sandbox probe from `/health` and names it.
