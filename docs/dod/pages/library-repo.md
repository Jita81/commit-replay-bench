# Context library (one page per work type)

**Purpose.** What people know about one repository that a test cannot say, in one vocabulary,
with one page per kind of change; each entry needs a sponsor and a different approver, and
nothing here reaches a builder until an arm has measured it (`help.ts` About copy; ADR-0026
item 10, DL-087).

**Entry → exit.** Arrives from the repository's page (*Context library*) or from a library row
on Decisions (an entry to sign, an entry gone stale, an entry retired by measurement). The
person leaves having read one work type's page — what it is and example commits, what a ticket
must carry, the signed context with sponsor, signer, date, provenance and effect, what is
proven per size, and which switched-on checks evidence which ISO/IEC 25010 characteristic —
or having proposed, sponsored, signed, revoked or retired an entry, each recorded with their
name, or having run the miners over the repository's files at a commit and been told what they
proposed.

**Non-goals.** It does not put an entry into a builder's brief: that happens only inside a
measured context arm, off by default (ADR-0026 item 10, `product.truth.212`). It does not sign
or sponsor what the miners propose from the repository's files (`product.extensibility.213`):
a person adopts each proposal and a different person signs it. It does not measure an entry's
effect (`product.truth.212`), or certify that code conforms to ISO/IEC 25010.
