# Ledger

**Purpose.** "Every graded trial, append-only and hash-chained. Verify proves nothing was edited, reordered or removed; the false-Q1 total is the number everything else defends." (`help.ts`, About block; page header `Instrument · Ledger`.)

**Entry → exit.** Arrive from the instrument nav "Ledger" — the one instrument entry a viewer has (`Layout.tsx:122`) — from the shell's stop-condition banner ("Investigate in the ledger"), from a Capability cell's "rows" button (class and size carried in the URL), from the Results page's ledger button, or from a Decisions `do_not_ship` "Investigate" action. Leave with the chain gate's state, the false-Q1 total, a filtered page of rows whose URL can be shared, a task opened at `/tasks/:repo/:taskId`, or a downloaded export — JSONL or CSV for anyone who can read, the abstract cell export for an operator.

**Non-goals.** Does not verify on demand — the server verifies on every read and an operator's own verification is `crb ledger verify` on the export; does not edit, repair or delete a row (append-only: a break is a finding); does not explain a cell's rate (the Capability page does); does not start, cancel or re-run anything; does not expose every filter `GET /grades` accepts.

## Gaps
- **G-180** — Four filters are invisible: the page reads `run_id`, `task_id`, `builder` and `language` from the URL but offers no control for them (`LedgerPage.tsx:68-80` reads nine keys, the card shows five), so Matching rows can be a fraction of the ledger with nothing on screen saying why · render one chip per active filter above the table, each removable, and unit-test that arriving at `?run_id=…` shows the chip · ui
- **G-181** — The empty state says "No rows match" and nothing else: no way to clear the filters, and no test asserts either wording (`LedgerPage.tsx:243`) · give the filtered empty state a "Clear filters" action that resets the URL, and assert both the filtered and the empty-ledger reason in `LedgerPage.test.tsx` · ui
- **G-182** — The three exports are plain download anchors, so a refusal is invisible: `GET /ledger/export/abstract` answers 409 while a false-Q1 row exists (`docs/API.md`) and the person gets a raw API response, not a message on the page · fetch the export in the click handler and render the envelope's message beside the button on a non-200, with a unit test for the 409 · ui
- **G-183** — No test renders this page's failure states: the gate is mocked `ok: true` in the unit tests and walked only OPEN with false-Q1 = 0 (by design, 01-login), so `broken_at` and a red false-Q1 tile are never seen; the CSV and abstract exports are never downloaded in a walkthrough · add two `LedgerPage.test.tsx` cases (`ok: false, broken_at: n` and `false_q1_total: 1`) asserting the CLOSED gate, the red tile and the banner wording · ui
- **G-184** — No audit event records an export: `src/crb/server/routes/ledger.py` writes no system event, so who downloaded the rows, the CSV or the abstract cells, and with what filter, is not recoverable (`DATA-RETENTION.md` §4 access) · append one `ledger.exported` event with actor, format and filter on each export route and assert it in `tests/test_server_routes_ledger.py` · server
- **G-185** — The page states no non-goals, and the header sentence "Verify proves nothing was edited…" reads as a button that is not there (the check runs server-side on read; the operator's own verification is `crb ledger verify` on an export) · add one sentence to the About block naming what the page does not do and where verification is performed · ui
