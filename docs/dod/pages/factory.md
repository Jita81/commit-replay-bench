# Factory

**Purpose.** Deliver new work under the same rules as replay: a frozen backlog, a failing test proved before any build, a build inside the sandbox, and a branch and pull request only where the map routes deliver — every step on the evidence chain (`help.ts` About copy; eyebrow "Journey · 4 of 4 · Factory").

**Entry → exit.** Arrives from the nav, from Home task 8 ("Deliver your first change" / Continue while a factory run works an item), from a Decisions row with `?repo=&item=` (gap to sign, item routed to human, rework, delivery withheld), or from the repository's Next steps; with no `?repo=` the most recently updated repository is chosen, and with nothing connected the only exit is Connect. The person leaves with a frozen backlog (`frozen · hash · n items`), a queued factory run they can open at `/runs/:id`, and per item a six-step chain ending in a pull request link on the customer's repository or the sentence that says why delivery was withheld.

**Non-goals.** It is not a full run form — it runs the deployment's builder, or one an operator names, with no ladder or executor knobs. It does not sign off a cell, change the map's route, review a diff, or merge the pull request it opens: the merge is a person's decision on the customer's repository. Two things this page does not do are not non-goals: work from a ticket system arrives through intake (`/factory/intake`, ADR-0022), not through the freeze form; and a spend cap per run is the operator's to set in Before you run, which the run keeps item by item (F5b).

- **G-978** — `docs/OPERATOR.md` has no section on running the factory — §10 is the factory's test author and §11 its intake — so nothing says what a refused readiness, a withheld delivery, a read-only installation or a fetch that cannot fast-forward mean, and §8's stop conditions name none of them · add an OPERATOR section "Run the factory" (the next free number) with those four cases and their way forward, name them in §8, and reference it from the Factory About read-more · docs
- **G-933** — a ready ticket in a cell with no proven context standard is registered and built at the operator's cost and only its pull request is withheld, readiness asks the ticket for a hand-written slot catalogue rather than for its cell's measured standard, and a ticket's size comes from story points that nothing has checked against the churn its changes turn out to have · make readiness read the cell's standard arm from the signed map (ADR-0026) and ask the ticket for exactly what that arm needs; stop entry `no_proven_standard` or `needs_context` before any spend whether or not delivery is on; add the approver's evented calibration build that can never open a pull request; stop an unsigned cell before any spend and narrow `deliver_override` to that sign-off clause (ADR-0026 item 8); apply the more demanding of the named size's cell and the next larger one until the points-to-churn agreement passes (an ADR-0026 [operator] value: the operator may instead refuse every pointed ticket `size_unknown`); reword intake `recovery.23`, manufacture `non-goals.12` and factory `non-goals.19` to say so, with the hint copy that says items are built and withheld or that the override lifts the route (`stat.factory.deliverable`, `factory.cell_route.withheld`, `field.factory.override`) · factory
- **G-142** — no walkthrough opens a pull request from this page: 10-factory is tier 1 with `fixture_gold`, asserts "not linked — no pull request" and a disabled deliver checkbox, so delivery, rework and the outcome are proved by `tests/test_factory_delivery.py` only · add a tier-2 walkthrough against a scratch repository linked through the App that runs one item clean, delivers it and reads the PR link from the item row · ui
- **G-143** — the approver's two acts are unit-level only: signing a structural gap is asserted as a form in 10-factory and submitted in `FactoryPage.test.tsx`, and `deliver_override` appears in no walkthrough · walk both as the approver in 10-factory (sign the gap, then re-run with the override ticked) and assert the chain records the override under their name · ui
