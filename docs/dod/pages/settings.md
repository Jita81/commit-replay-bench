# Settings

**Purpose.** The instrument's health, the builder sign-in, the GitHub App and, for admins, the non-secret configuration and user accounts. Secrets are never returned by the API and never shown here (help.ts `/settings`).

**Entry → exit.** An admin arrives from the nav "Settings" link (shown to admins only; the route itself is open to every signed-in role), from Home task 7 "Invite an approver", or from a "Settings" link on a Posture row that is not the production posture. They read the health card (every probe with its detail line, and the crb · apparatus · policy version line), store or verify the Claude Code token, read the GitHub App state and sync its installations, read the redacted configuration (sandbox mode, ledger backend, apparatus, policy, OIDC, builders, retention), and create a local account or change a role in the Users card. A non-admin sees health, the token's presence and the GitHub App card, then a Configuration card that reads "Admin only" with the reason. The page offers guide links (Register the GitHub App, How credentials are held, When the sandbox is unavailable, How sign-in and roles work) and no in-app next step.

**Non-goals.** The page does not register the GitHub App (that is `CRB_GITHUB__*` on the host; the card says so and links the guide) and does not configure OpenID Connect (`CRB_OIDC__*`; shown read-only as enabled or disabled). It does not show a secret value: a builder is configured or not, a stored token is at most its last four characters. It does not run measurement.
