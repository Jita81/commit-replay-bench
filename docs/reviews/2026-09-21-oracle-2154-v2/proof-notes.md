- The `--config x` row now also asserts root's --config == "x": an extra observable beyond the verifier's four rows, true under the fix and under any build that parses the token with pflag on any command sharing the flag object.
- `--vroot`/`--config` are asserted via root.PersistentFlags() after Execute; pflag AddFlagSet shares the *Flag, so a build that parsed them on the help command's or sub's merged flag set both satisfy the value assertion — the rows reject builds that refuse, mis-route or mis-consume the token, not builds that parse it on a different inherited copy (there is none).
- `help sub -h` is a behaviour change from the base (base shows help for the help command); it is pinned as an observable of the correct fix (non-interspersed parsing on the help command).

## Residue (accepted)
This oracle is frozen at rev 5. The following wrong-build families are NOT excluded by it, and the size gate (size_estimate S, i.e. < 40 changed source lines) is what catches them:
1. A faithful pflag re-implementation on the help command. A build that disables flag parsing on the help command and re-implements, by hand, pflag's full behaviour for the tokens before the topic — long and shorthand forms, grouped shorthands, `--flag=value` including `=1` and the empty `=`, value-taking flags with a separate value and the missing-value error, unknown-flag and unknown-shorthand errors, `--` termination, NoOptDefVal, every inherited persistent flag by name — then stops at the topic and forwards the rest to the helped command's own parser, can satisfy every row here. The verifier's walker D (35 source lines) is the closest such build and is now rejected on four pflag corner cases; the next iteration (bounds check on the value read, nil check on ShorthandLookup, `--` handling, empty-value `=`) is ~10-15 lines more, i.e. ≥ 45 changed source lines. Why the size gate catches it: the correct fix is 16 lines; any hand-rolled parser that survives (a)-(d) plus the seven rev-4 rows is a parser, not a two-branch fix, and lands at ≥ M. The oracle cannot be extended to exclude this family without enumerating pflag, and each row it adds only pushes the family's line count up — the gate is the right instrument.
2. Builds equivalent to the correct fix on this fixture but wrong on flag kinds the fixture does not declare (e.g. slice or count flags, `--flag=a,b`, negative numbers as values, `-c=3` shorthand-equals form, `--config -x` where the value looks like a flag). The fixture declares int/bool on sub and string/bool on root; a build that special-cases those kinds passes. Such a build is again a hand-rolled parser (≥ M); a pflag-based build is uniform across kinds by construction.
3. Builds that reproduce the correct fix's observable behaviour through a different mechanism that the fixture cannot see — e.g. re-parsing the tokens after the topic on a fresh copy of sub's flag set rather than sub's own (pin 3 catches a copy that is not written back, not one that is written back afterwards), or achieving non-interspersed parsing by re-ordering tokens. These are behaviourally equivalent for the pinned observables; if they are also small they are acceptable deliveries, not wrong builds.
4. Attack A's family (keep pflag on the help command; hand-rolled filter for the tokens after the topic) is rejected only by pin 3 (`--count` reads 7 inside the help function). A filter that additionally sets the flag values it strips is again a parser (A is already 42+3 lines) → size gate.
No further attacks are attempted after this revision.
