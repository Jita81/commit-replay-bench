## Item 1. The added integrity stop

**Words relied on.**

- REG 870-873 (A3): "Clean is read from the row's own field in the product ledger. Nobody re-grades a
  row. A row that carries an error is a miss, not a gap. ... No row is dropped, replaced or run again."
- REG 859-860 (A2 item 2): "the rows from that arm's two runs in the commit's batch".
- REG 1040-1042: "If any part fails, or a field it needs is absent, it stops ... and prints no figure."
- REG 1102-1103: "Until the output is filed, nobody computes a clean count by arm, by repository, by cell or by batch".

**Reading.** The stop is not written in the registered text. It is still within it. A row that names
another run, a task not on the list, a second row for one task, or a `clean` that is not a boolean
cannot be scored without someone choosing a row or a value. A3 forbids that choice. The only act
that makes no choice is to stop and print no figure. The stop can never produce a result or move
one. It narrows; it loosens nothing. The text does not settle it, so the harder reading is taken:
stop, exit 4, no figure.

Two limits go with it.

1. A row that is merely absent is not an integrity fault. It is a miss (REG 217, 385-386). The script
   keeps these apart (SCRIPT 1525-1548 and the comment at 1855). That is right.
2. Rows were read before this stop. So what follows it is not mine to rule. See item 13.

**Does the script meet it?** Yes. `main`, SCRIPT 1855-1884: two counts, no figure, ids to the
deviation file, exit 4. The deviation lines lack the two times; that is item 3.

## Item 2. T1-T3 stops print no run id and no time

**Words relied on.**

- REG 1041-1042: "it stops, prints which part failed with the run ids and times concerned, and prints no figure."
- REG 1056-1058 (c): "Both are read from the run record as the product serves it. Nothing else is used as a time, and no seat types one in."
- RUL 506-509: every failure prints its part with the run ids and times.

bars any other time: the script may not print `posted` or `ended` from an out file, nor a typed
time. Printing none is the only reading that keeps (c). The text settles it.

The harder reading adds one thing. The output must say so in words, so that a reader does not take
the silence for a dropped line.

**Does the script meet it?** In substance yes: `main`, SCRIPT 1720-1756, calls `print_failures` with
an empty run map before any request. It does not print the explaining line.

**Change (C1).** On every stop made before the first request (T1, shape, T3, T2, and T4 when no
record was fetched), print one fixed line after the failed part:
`No run record was read. No run id and no time is concerned.`
Where T3 or T4 names a well-formed run id, the id is printed and its times read `NOT KEPT`, as
`_times` (SCRIPT 1334-1340) already does.

## Item 4. The line "Rows read: N of 240 (48 runs x 5); rows missing: M (each counted as a miss, A3); first filing 98fe708c: set aside unread."

**Words relied on.**

- REG 859-860: "That is 4 rows a commit, 240 rows in all."
- REG 846-847 (A1): "48 standing runs, each `succeeded` with 5 of 5 rows".
- REG 217: "After that, a row that is still missing counts as a miss."
- REG 385-386 (part 6 item 5): "Disqualified rows, missing rows, outages ... all count as misses, under both arms."
- REG 868-873 (A3) quotes item 5 and then says: "The 240 rows all exist".
- REG 862-864 (A2 item 3): "The first filing (run `98fe708c`, failed, 0 rows) is "set aside unread" (part 2, row rule). It holds no row, so nothing is set aside in practice."
- REG 200-202: "Rows still missing after the batch is filed again count as misses and can move the primary result, so the report lists every such row with its batch and arm."

**Reading, word by word.**

- "of 240 (48 runs x 5)": supported (REG 846-847, 860).
- "Rows read: N" and "rows missing: M": allowed. They are totals over all 48 runs. They are not by
  arm, repository, cell or batch, and they are not clean counts. They sit inside the one output.
- "each counted as a miss": supported, but the citation is thin. A3 only quotes the rule. The rule
  itself is the row rule (REG 217) and part 6 item 5 (REG 385-386). The line must cite those.
- "first filing 98fe708c: set aside unread": these are the registered words of A2 item 3. Supported.
  The short id is the one the registration prints. The harder reading adds the registered
  qualifier, so nobody reads the line as rows put aside: it held 0 rows.
- If M is above 0, the line alone is not enough. A3 records that all 240 rows exist, so M above 0
  departs from a recorded fact. REG 200-202 also makes the report list each such row with its
  batch and arm. The script runs once (REG 1098), so the list must come out of that one run.

**Does the script meet it?** Not fully. `print_read`, SCRIPT 1611-1612, cites A3 alone and prints no
list of missing rows.

**Change (C3).** Print the line as:
`Rows read: N of 240 (48 runs x 5); rows missing: M (each counted as a miss: row rule, part 6 item 5, A3); first filing 98fe708c: set aside unread (0 rows, A2 item 3).`
When M is above 0, print next: `A3 records that all 240 rows exist. M do not. This goes into the deviation log.`
Then, after the decision word, list each missing row with its run id, task, batch and arm
(REG 200-202). The list goes after the decision word so that it stays part of the filed output and
nothing by arm is printed ahead of the result.

## Item 5. Spec open point 5: t quantiles rounded up to 4 decimals

**Words relied on.**

- REG 329-330: "the 97.5% point of Student's t with `B − 1` degrees of freedom".
- REG 915: "Student's t with 11 degrees of freedom (2.2010)".
- REG 916-917: ""Below 15 points" is compared without rounding."
- REG 363-366: *No 15-point effect* needs "the upper end below 15 points of the primary interval and of both recomputed intervals".

**Reading.** For 11 degrees of freedom the registration prints the value, 2.2010. The script uses it.
The text settles that. For fewer degrees of freedom (the recomputed results) the text names the
point and prints no digits. A table needs some rounding. Rounding up makes the interval a little
wider. A wider interval can only block *No 15-point effect*. It cannot help *Cleared*, which rests
on p and the sign. The text does not settle it, so the harder reading is taken: round up. "Without
rounding" (REG 916-917) is about the comparison with 15, and the script keeps it.

**Does the script meet it?** Yes. Table at SCRIPT 212-226; used in `compute` 1433-1448 and
`upper_end_below` 1417-1420. The comment at 212 states the rule. No change. The report states the
rule in one sentence beside the interval.

## Item 7. Spec open point 16: time precision

**Words relied on.** REG 1058-1060 (c): "Times are compared as instants, with their time zone, at the

## Item 9. "The run value" is an object, not a run id; the script reads only `run.id`

**Words relied on.**

- REG 1642-1644 (Point 1): "From an out file the script reads the run id under each key and nothing else."
- RUL 138-140 (T4): "The 49 `run` values must be 49 different full run ids."
- RUL 262-267: "For each of the 49 keys, the `run` value. Nothing else. The script drops `arm`, `posted`, `ended` and `clean_end` as it parses, and never stores, logs or prints one."
- RUL 271: "**Nothing else from that folder.** No response, poll, log or login file."
- RUL 560-564: the out-file guard keeps `run` only.

**Reading.** The ruling wrote "the `run` value" on the belief that it is the id. In the real file it
is an object: `id`, `status`, `progress`, `clean`, `errors`, `stopped_reason`, `stopped_code`,
`cost_usd`, `error`. Every field but `id` is outcome-level. The registered words of Point 1 are the
later and the narrower: "the run id under each key and nothing else". They govern. Reading
`run.id` alone is inside both texts. Keeping the whole object would break Point 1, the guards of
RUL section 5 and REG 1102-1103. So:

1. The script takes `entry["run"]["id"]` and nothing else. It never binds, stores, logs or prints
   another field of the object, nor the object itself. This holds on failure paths too.
2. If `run` is not an object, or `id` is not a string, T4 fails. The script must not fall back to
   reading `run` as a string.
3. Condition 5 ("nothing else from that folder") is kept: same two files, fewer bytes kept.

**Does the script meet it?** Yes. `extract_out`, SCRIPT 598-624. No change to the code.

**What the wave record must say.** The out files' `run` value is an object. The ruling assumed an id.
The script reads `run.id` only, under Point 1's words. This is recorded before the read.
